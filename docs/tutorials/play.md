文書状態: DSL 4.0リリース前draft。公開手順としては未確定です。\
対象: 初めてTMPose紙芝居を再生する人\
対象仕様: `kamishibai: '4.0'`\
想定時間: 10〜15分

このチュートリアルでは、ブラウザでサンプル作品を開き、カメラの前でポーズを取り、物語を
最後まで進めます。台本、SB3、CLI、TurboWarpのコード領域は扱いません。

## 完了するとできること

- サンプルサイトからWeb版の紙芝居を開ける
- カメラ利用を許可し、previewへ自分の姿を収められる
- ポーズ認識の案内と進捗を見ながらポーズを取れる
- 終了後にもう一度遊ぶか、タイトルへ戻れる
- カメラやポーズ認識が進まないときに基本項目を確認できる

## 始める前に

正式リリース時に、対応browser、必要なnetwork接続、camera要件、推奨する明るさと撮影距離を
ここへ記載します。初版の画面説明はdesktop browserを基準とし、mobile固有の許可画面が操作上
大きく異なる場合だけ補足します。

## 1. サンプル作品を選ぶ

公開サンプルサイトでチュートリアル用の最小作品を開きます。作品詳細には、対象DSL version、
所要時間、camera利用の有無、Web版を開く導線を表示します。

<!-- screenshot:P-01 -->

リリース後に、固定した作品名、公開URL、導線の正式な表示名を記載します。

## 2. 紙芝居を開始する

Web版を開くと、DSL 4.0 app shellのタイトル画面が表示されます。開始操作を行うと、台本と作品に
必要なアセットの検証・準備が始まります。

<!-- screenshot:P-02 -->

Loading中は画面を閉じず、準備が終わるまで待ちます。進捗表示の意味と、長時間変化しない場合に
確認する項目は正式なapp shellへ合わせて確定します。

<!-- screenshot:P-03 -->

## 3. カメラを許可する

ポーズ認識を始めるとき、browserがcamera利用の許可を求めます。この作品でポーズを使うには、
現在のsiteに対するcamera利用を許可します。

<!-- screenshot:P-04 -->

許可しなかった場合や、以前の選択が残っている場合の再設定方法は、対応browserごとの正式な
手順が固定されてから補います。

## 4. ポーズを取る

camera previewへ全身が入る位置に立ち、作品内の案内に合わせてポーズを取ります。認識中の画面は、
少なくとも次を区別して伝えます。

- 現在求められているポーズ
- camera preview
- 現在の認識度
- ポーズを保った結果として進むチャージ
- 認識待ち、チャージ中、完了の状態

<!-- screenshot:P-05 -->

ポーズが成立すると、音、表示、次のsceneへの進行など、作品に設定された成功feedbackが起きます。

<!-- screenshot:P-06 -->

## 5. 最後まで進める

画面のセリフや案内に従い、最後のsceneまで進めます。終了状態では、もう一度遊ぶ操作とタイトルへ
戻る操作を区別して説明します。

<!-- screenshot:P-07 -->

## 6. うまく進まないとき

次を順番に確認します。

| 状態                   | 確認すること                                                     |
| ---------------------- | ---------------------------------------------------------------- |
| camera映像が出ない     | browserとOSのcamera許可、他applicationによるcamera利用を確認する |
| 体が画面へ収まらない   | cameraから離れ、頭から足まで入る位置へ移動する                   |
| 認識度が上がらない     | 明るさ、背景、服と背景の色、複数人の映り込みを確認する           |
| チャージが途中で戻る   | ポーズを大きく作り、同じ姿勢を少し長く保つ                       |
| 想定と左右が逆に見える | 正式UIでmirroring設定が提供される場合は表示状態を確認する        |
| 別のcameraを使いたい   | 正式UIでcamera選択が提供される場合は接続中のcameraを選び直す     |

camera選択とmirroring controlがStandard app shellへ採用された場合は、この位置へ操作画像を置きます。

<!-- screenshot:P-08 -->
