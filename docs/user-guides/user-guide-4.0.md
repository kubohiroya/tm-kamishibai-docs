## まず選ぶ

初めて試す場合は、必要なものを埋め込んだ「浦島太郎」のWeb版を使います。ブラウザだけで上演できます。

| 目的                 | 開くもの                                                                                                  | 特徴                                 |
| -------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| すぐ上演する         | [浦島太郎 Web版](https://kubohiroya.github.io/tmpose-kamishibai-samples/stories/urashima/web-4.0/)        | 必要なものを埋め込んだ上演用surface  |
| 自分のYAMLを読み込む | [私の浦島太郎 Web版](https://kubohiroya.github.io/tmpose-kamishibai-samples/stories/my-urashima/web-4.0/) | 起動後に`.k4.yml`を選ぶ              |
| 配布物を選ぶ         | [浦島太郎 作品ページ](https://kubohiroya.github.io/tmpose-kamishibai-samples/stories/urashima/)           | Web版、SB3、YAMLと完全性情報を選べる |

Web版は大きいため、安定した回線を使います。浦島太郎Web版は約67 MBです。カメラを使う場合は、HTTPSで開ける
パソコン、ブラウザのカメラ権限、全身または上半身を映せる明るい場所を用意します。周囲の人と物にぶつからない
距離も確保してください。

## 浦島太郎を最初から上演する

1. [浦島太郎 作品ページ](https://kubohiroya.github.io/tmpose-kamishibai-samples/stories/urashima/)を開く
2. 4.0の「Web」を選ぶ
3. ダウンロードと読み込みが終わるまで待つ。白い画面のまま操作を連打しない
4. タイトル画面で`Version 4.0.0 (2026/08/11)`と表示されることを確かめる
5. タイトル画面右上の「×」を押す
6. `Loading`表示が消え、最初の場面が表示されるまで待つ
7. 画面の案内に従ってキー、画面タッチ、またはポーズで進める

別の版表示だった場合は、そのまま本番に使わず、作品ページへ戻って4.0のリンクを開き直します。

## 上演中の入力

通常は作品内の案内に従います。進行役がリハーサルで先へ進める必要がある場合だけ、次のキーを使います。

| 入力         | 動作                       | 使う場面                               |
| ------------ | -------------------------- | -------------------------------------- |
| `Space`      | 現在のポーズ待ちをスキップ | ポーズを検出できず、進行を優先するとき |
| `ArrowRight` | 現在のアクションをスキップ | 発話や動作の待ちを先へ進めるとき       |
| `ArrowDown`  | 現在の場面をスキップ       | 場面単位で次へ進むとき                 |
| 画面タッチ   | 画面に表示された選択を実行 | タッチ案内が出たときだけ               |

キーを長押しすると意図せず複数段階進むことがあります。1回ずつ押し、画面の変化を待ってください。

## カメラとポーズを使う

### 初回の権限

1. ブラウザがカメラの使用を尋ねたら、参加者と進行役が同意してから「許可」を選ぶ
2. カメラ映像またはポーズ案内が表示されることを確かめる
3. 複数のカメラがある場合は、ブラウザまたはOSのサイト設定で使うカメラを選ぶ
4. 左右が分かりにくい場合は、プレビューの鏡像表示と実際の動きを一度確認する

カメラ映像を録画・保存する機能として扱わず、会場でも画面の撮影範囲に第三者や個人情報が入らないようにします。
終了後はカメラ使用中の表示が消えたことを確認します。

### ポーズ判定

ポーズ待ちでは、画面内に体を収め、見本に合わせて静止します。判定の確信度が足りない間は、次の点を順に確認します。

- 逆光を避け、顔と腕の輪郭が見える明るさにする
- カメラから少し離れ、必要な関節を画面内に入れる
- 背景と服の色が近すぎる場合は位置または背景を変える
- 鏡像に惑わされず、画面のポーズ案内に合わせる
- 充填表示がある場合は、満ちるまで姿勢を保つ

2026年8月11日の実機検証では、カメラ映像を入力にしたポーズ成立と進行を確認しました。検証記録は
[上流Issue #510の実機結果](https://github.com/kubohiroya/tmpose-kamishibai/issues/510#issuecomment-5255177777)にあります。

## 自分のYAMLを読み込む

「私の浦島太郎」Web版は、外部の`.k4.yml`を選んで上演する確認用surfaceです。

1. [私の浦島太郎 Web版](https://kubohiroya.github.io/tmpose-kamishibai-samples/stories/my-urashima/web-4.0/)を開く
2. タイトル画面の版表示を確認し、右上の「×」を押す
3. 読み込みメニューでYAMLを選ぶか、案内された領域へ`.k4.yml`をドロップする
4. 診断がないことを確認してから上演を始める

選んだファイルだけでなく、そこから参照する画像、音声、includeも必要です。ブラウザが参照先を読めない場合は、
作者が配布したproject一式を同じ構成で用意します。ファイルを選んだだけで自動的に安全な上演になるとは
保証しません。知らない配布元のprojectは読み込まないでください。

台本を作成・修正する場合は、操作説明を広げず
[紙芝居DSL 4.0 台本作成ガイド](../dsl-author-guides/dsl-4.0-author-guide.md)を参照します。

## 終了と再実行

最後の場面または終了表示まで進んだら、音声が止まり、カメラ使用中の表示が消えたことを確認します。

- 同じ作品を最初から見る: ブラウザを再読み込みし、タイトル画面からやり直す
- 別の作品を開く: 作品ページへ戻り、別のWeb版を選ぶ
- SB3を再実行する: 停止してから緑の旗を押す
- 完全に終了する: タブを閉じ、ブラウザやOSのカメラ使用中表示が消えたことを確認する

再読み込み後もカメラ表示が残る場合は、同じサイトを開いている別タブを閉じます。それでも消えない場合は、
ブラウザを終了してからOSのカメラ表示を再確認します。

## 困ったとき

| 状態                         | 確認と戻り方                                                                               |
| ---------------------------- | ------------------------------------------------------------------------------------------ |
| タイトルが出ない             | 回線を確認し、読み込みを1回だけやり直す。約67 MBを取得できる環境へ移る                     |
| `Loading`から進まない        | タブを再読み込みする。繰り返す場合は作品ページのSB3を使って切り分ける                      |
| カメラを拒否した             | ブラウザのサイト設定でカメラを許可し、ページを再読み込みする。許可できなければキーで進める |
| 違うカメラが映る             | サイト設定またはOS設定で入力カメラを選び直し、他のカメラ利用アプリを閉じる                 |
| 左右が逆に見える             | 鏡像は自然な操作のための表示である。画面の案内に合わせ、必要なら立ち位置を入れ替える       |
| ポーズが成立しない           | 明るさ、距離、全身の収まり、背景、静止時間を確認する。進行優先なら`Space`を1回押す         |
| 画像や音声が見つからない     | project一式と相対pathを確認する。欠けたまま続けず、配布元から再取得する                    |
| YAMLの診断が表示された       | 診断のfile、path、codeを記録して上演を止め、作者へ渡す。直前に成功したprojectへ戻す        |
| 音声が出ない                 | 端末の音量、ミュート、ブラウザの自動再生制限を確認し、タイトル画面から操作をやり直す       |
| 終了後もカメラ表示が消えない | 同じサイトの別タブを閉じ、ブラウザを終了する。OSのカメラ表示が消えるまで次の利用へ進まない |

診断が出た場合は、個人情報を含まない範囲で次を記録します。

- 開いた作品ページとWeb版のURL
- タイトル画面の版表示
- 診断の`code`、`file`、`path`、メッセージ
- 直前にした操作
- ブラウザとOSの名前

カメラ画像そのものは診断記録へ添付しません。

## ロールバック

公開Web版で上演を継続できない場合は、同じ作品ページのchecksum付きSB3へ切り替えます。Web版を公開する
運用者は、サンプルのWeb公開フラグをOFFにしてリンクを隠し、修正版を検証してから戻します。参加者の端末では
問題のタブを閉じ、カメラ使用中表示が消えたことを確認してください。

この説明書には正式UIの画像を掲載していません。操作の順序、表示文字列、公開URL、checksumを文章・表で
確認できるためです。将来画像を追加するときは、capture台帳で版、URL、撮影日時、権限状態を固定します。
